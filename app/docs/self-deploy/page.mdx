# Self-deploy

Run Thoughtstead from your own terminal — locally first if you like, then to
your own hosted Vercel + Supabase project. This is the path for people who
are comfortable with `git` and `npm` and want full control.

## Clone and configure

```bash
git clone git@github.com:thoughtstead/thoughtstead.git && cd thoughtstead
cp .env.local.example .env.local
```

Then fill in `.env.local`. Every variable, in order, with what it means:

| Variable | What it's for |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | From `supabase start` output (hosted: project API settings) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | From `supabase start` output (hosted: project API settings) |
| `SUPABASE_SERVICE_ROLE_KEY` | From `supabase start` output (hosted: project API settings) |
| `SUPABASE_JWT_SECRET` | JWT signing secret — local: `supabase status` "JWT secret"; hosted: project API settings |
| `OPENROUTER_API_KEY` | From [openrouter.ai/keys](https://openrouter.ai/keys) — pay-as-you-go, $10 lasts months |
| `EMBEDDING_MODEL` | OpenRouter model id; embedding model is fixed per-instance after setup |
| `METADATA_MODEL` | OpenRouter model id |
| `AGENT_MODEL` | OpenRouter model id |
| `CRON_SECRET` | Any random string; must match the Authorization bearer sent by Vercel cron |
| `GOOGLE_CONNECTOR_CLIENT_ID` | Your own Google OAuth app (Gmail + Calendar sync). Create at [console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials) — OAuth client (Web application) with the redirect URI below; enable the Gmail and Calendar APIs |
| `GOOGLE_CONNECTOR_CLIENT_SECRET` | Same Google OAuth app as above |
| `GOOGLE_CONNECTOR_REDIRECT_URI` | The redirect URI registered on that OAuth client |
| `CONNECTOR_TOKEN_KEY` | AES-256 key for encrypting connector OAuth tokens at rest (base64, 32 bytes). Generate with `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` |
| `DIAGNOSTICS_ENDPOINT` | Optional. Where the opt-in, content-free daily diagnostics ping (app version + per-check pass/fail booleans only) is POSTed. Unset = diagnostics cron no-ops |
| `NEXT_PUBLIC_REPO_SLUG` | Optional. `"owner/repo"` for the Health page's best-effort update check against the GitHub releases feed. Unset = Health shows the version but skips the check. E.g. `thoughtstead/thoughtstead` |
| `CHAT_MODEL` | Chat model for in-app AI chat (OpenRouter id). Default: `google/gemini-2.5-flash` |

You don't need the `GOOGLE_CONNECTOR_*` or `CONNECTOR_TOKEN_KEY` values to get
started — leave them blank and Thoughtstead runs fine without Gmail/Calendar
sync until you're ready. See [Gmail & Calendar](/docs/connectors) for that
setup.

## Run it locally

```bash
npx supabase start
npx supabase migration up
npm install
npm run dev
```

`supabase start` brings up a local Postgres + auth stack in Docker and prints
the URL, anon key, service role key, and JWT secret you need above.
`supabase migration up` applies the schema. From there, `npm run dev` starts
the app.

## Deploy it hosted

For a hosted instance under your own accounts:

1. **Database:** create a Supabase project, then link your local checkout to
   it and push the schema:
   ```bash
   npx supabase link
   npx supabase db push
   ```
2. **App:** create your own Vercel project from this repo and set the same
   environment variables there (using your hosted Supabase project's values
   instead of the local ones).
3. **Crons:** scheduled jobs (nightly enrichment, connector sync, imports,
   agents, diagnostics) come from `vercel.json` in the repo. On Vercel's
   Hobby tier, crons run once daily; if you're on Vercel Pro you can tighten
   the schedule in `vercel.json` for more frequent syncing.

Once deployed, migrations apply automatically as part of every Vercel build —
you don't need to run `supabase migration up` again for hosted deploys.

  Never run `supabase db reset` against a database that has real data in it —
  it wipes everything. Use `supabase migration up` to apply new migrations to
